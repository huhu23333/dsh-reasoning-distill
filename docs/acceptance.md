## 一、设置项（设置 → 推理蒸馏）

设置页自上而下的区段：**总开关 → 助手消息改写后端（含分支超时）→ 默认规则 → 逐模型规则 → 价格 → 提示词**。

### 1. 总开关

| 设置项 | 默认 | 含义 | 影响 |
|---|---|---|---|
| 启用思考压缩（`enabled`） | 开 | 插件总开关。关闭后不再有任何蒸馏调用 | **未选择改写后端时被强制关闭并置灰**（面板、引擎、报告三处一致）；选择后端后解锁，是否打开由你决定 |

### 2. 助手消息改写后端

| 设置项 | 默认 | 含义 |
|---|---|---|
| 助手消息改写后端（`rewriteBackend`，单选） | **空（不选）** | 谁来把蒸馏结果**写回会话历史**。只列出已安装的后端（探针规则见下），未安装的置灰；点已选中的那行=取消选择 |
| 分支超时（毫秒）（`branchTimeoutMs`） | **0** | 宿主等待**分支型**后端建好分支的时限；**0 = 永不超时**。仅选中分支型后端时可编辑，否则置灰 |

三个后端及其契约：

| id | 前置插件 | 请求 | 语义 | 谁来调用 |
|---|---|---|---|---|
| `message-edit` | `dsh-message-edit`（或 `@yunyv/dsh-message-edit`） | `POST /message-edit {action:'edit', sessionId, eventSeq, blockIndex, text, cascade:'truncate'}` | **另开分支会话**（新版本，原会话不动） | **宿主**（`127.0.0.1:<webServer.port>`，无需浏览器凭据）→ 能在请求发出前完成 |
| `msg-edit` | `@moton16/dsh-msg-edit` | `POST /api/msg-edit/rewrite-message {sessionId, messageId, reasoning}` | **就地**改写模型可见历史（不截断后续） | **面板**（该路径需浏览器凭据） |
| `context-shaping` | `zeranhub/dsh-context-shaping` | `POST /api/dsh-context-shaping/edit {sessionId, messageId, part:'thinking', role:'assistant', text}` | **就地只改思考部分** | **面板** |

**安装探测**（界面挂载时对每个后端发一次探针）：**`404` 且响应不是 JSON** 才算"未安装"——已安装的后端连自己的错误（会话不存在、请求体不合法）也是用自己的 JSON 信封回答 404。

### 3. 默认规则 / 逐模型规则（同一组字段）

| 字段 | 默认 | 含义 |
|---|---|---|
| `enabled` | 开 | 对**主对话**启用 |
| `continuableSubagents` | 开 | 对**可续接子代理**（队友等）启用 |
| `continuableMaxDepth` | 0 | 可续接子代理的**最大生效深度**（0=不限制） |
| `oneShotSubagents` | 关 | 对**一次性子代理**启用 |
| `oneShotMaxDepth` | 0 | 一次性子代理的**最大生效深度**（0=不限制） |
| `thresholdTokens` | 4000 | **触发门槛**：该步思考估算 token 超过它才尝试蒸馏 |
| `minSavedTokens` | 600 | **采用门槛**：蒸馏后若 `原估算 − 蒸馏估算 < 此值` 则**不替换**（记"未采用"条目，开销照记） |
| `includeToolResults` | 开 | 是否把该步工具**结果**作为背景交给蒸馏 |
| `includeFinalTurns` | 开 | 最终回答那一轮（无工具调用）是否也压缩 |
| `timeoutMs` | 60000 | **单次蒸馏**时限（0=不限）；超时即放弃该次压缩、原文不动 |
| `distiller` | deepseek-official / deepseek-flash / off | 蒸馏用的 provider/模型/推理档 |

四种会话种类的开关各自独立；**每条规则三档全关**时其余字段置灰（不可能生效）。逐模型条目**稀疏存储**：只写被改过的字段，其余继续跟随默认规则。

### 4. 价格

| 设置项 | 默认 | 含义 |
|---|---|---|
| 峰谷计价开关（逐模型 `peakPricing`） | DeepSeek 内置模型开 | 该模型是否按峰/谷两栏计价 |
| 峰/谷 命中·未命中·输出 单价（逐模型） | 内置价目 | 用于把 token 折算成钱 |
| 时段来源（`peakSource`） | builtin | `builtin`=内置节假日表；`whale`=按本机 whale 引擎的判定 |
| 节假日表（`holidays`） | 内置 | 全天按谷价计价的日期（北京时间） |

### 5. 提示词

| 设置项 | 默认 | 含义 |
|---|---|---|
| 蒸馏提示词（`prompt`） | 空 = 内置 | 你自定义的系统提示词；清空即恢复内置。内置文本经 gpt-6-astra 审阅定稿 |
| 蒸馏输入上限（`maxInputChars`） | 120000 | 工具结果等背景块的单块长度上限（防一块超长输出独占输入） |
| 蒸馏输出上限（`maxOutputChars`） | 0 | 蒸馏结果长度上限，0=不限 |

## 二、显示项

### 会话页 → 推理蒸馏 标签

**四张金额/数量卡**（符号约定统一为"一本账"：**正数=多花，负数=省下**，红正绿负）：

| 卡片 | 主值 | 小字 | 含义 |
|---|---|---|---|
| 触发次数 | **成功 X** | 尝试 Y · 约 **−Z** tokens（历史减量） | 成功=真正采用了改写的条目；尝试=记过的条目总数（含蒸馏失败、节省不足未采用） |
| 蒸馏开销 | **+¥…** | 蒸馏 input+output token | 各次蒸馏**实际花掉**的钱（失败/超时/未采用也计） |
| 当前单次请求减量 | **−¥…** | 约 **−N** tokens · 口径说明 | **存量**：此刻仍生效的改写让**这一次请求**少带的估算 token，金钱按**命中价**估算；不随请求次数增长 |
| 历史累计节省 | **−¥…** | 约 **−N** tokens（历史累计） | **流量**：每次确实带着这些改写发出的请求，按**那一次实际适用价格**结算并累加，**永不重置**（条目失效后其历史贡献保留） |
| 净收益 | **−¥…**（省）/ **+¥…**（亏） | 同上累计 | 历史累计节省 − 蒸馏开销 |

**说明文案**：存量口径、符号约定、整段压缩后的归零规则。

**进行中区**：正在运行的压缩（轮次/步、蒸馏器、原 token→当前）、阻塞横幅（原因：工具调用中/等待用户/其它 + 已等待秒数）。

**触发记录（逐条，可展开）**：
- 折叠行右侧：**`+增加开销 − 已避免开销 = 实际开销变化量`**（右对齐、红正绿负）；
- 展开后：该步**原文思考**（可复制）、**蒸馏结果**（可复制）、每次蒸馏的模型/耗时/输入·缓存·输出 token/费用/时段，以及**当前单次请求减量**（token）与**已避免开销（负数）**、**一手历史累计 token**；
- **分支交接记录**：成功→「已创建分支 <id>」；失败→「分支创建失败：<原因> · 已按原会话继续」。

**审计会话列表**（弹窗）：每条压缩对应的会话 id；在线可打开，来自上次运行则标注「会话已随上次运行结束」并仍提供打开，且完整提示词/结果始终在本条明细里。

### 输入框活动指示器（composer）

压缩进行中/等待压缩完成时显示状态与原因，并**向宿主申请展开空间**（宿主据此隐藏模型/右侧控件）；压缩结束或读取失败即回到静默。

### 设置页自身的状态显示

保存状态（未保存/保存中/已保存/冲突/失败），目录加载失败提示与重试按钮，模型候选列表（可搜索、已加入项标 ●）。

## 三、后台处理逻辑（逐步）

### A. 会话接入（`session/created`）
1. 记录会话归属（自身创建的审计会话不参与）。
2. `Object.defineProperty` 包装该会话的 `deriveMessages()`；同时保存**原始**派生函数（给存量计算用）。
3. 预读该会话的 sidecar（fire-and-forget，单飞）。

### B. 逐步观察（`session/event`）
- `assistant/message`：
  1. 忽略中断（`interrupted`）的步骤；忽略非助手消息。
  2. 取该模型规则；判定**会话种类**（主对话/可续接/一次性）与**深度上限**，三档开关逐一放行。
  3. 估算该步 reasoning 的 token：低于 `thresholdTokens` → 不处理。
  4. 记住该步的载体信息（turn/step、消息 id、**reasoning 块下标**、可见 text 块与工具调用块）。
  5. **记账**：以"事件发生时刻的 surface 快照"判定该请求实际带上了哪些改写，按命中/未命中价累加（详见 D）。
- `step/end`：
  1. **先读记录**（`ensureLoaded`）：读不到（损坏/无权限）→ 标记该会话存储不可用，**跳过本步**，不花一分钱。
  2. 读得到 → `launch` 启动蒸馏（后台异步），并把这一整套登记为 in-flight。
- `compaction/end`：逐条判定改写是否仍会被应用，失效者结转 `frozenSaved`、标记 `inactive`；仍存活者保留并标记"下一次按未命中价结算"。

### C. 一次蒸馏（`compress()`）
1. 组装输入：`## Original reasoning`（要改写的部分）+ `## Assistant text from this step`（该步可见 text，**背景**）+ `## Tool calls from this step`（**背景**）+ `## Tool results`（按 `includeToolResults`，**背景**）；三段背景都标注 `(context only, never copy)`。
2. 用该规则的 `distiller` 发一次独立调用（超时按 `timeoutMs`，0=不限）；输出长度按 `maxOutputChars` 裁剪。
3. 用量与费用：优先用返回的 usage，缺失则按字符估算并标记"估算"；费用按当时时段/命中·未命中价折算。
4. 创建**审计会话**（把完整提示词与结果写进它的持久化日志）；创建失败记 `sessionMissing`，但压缩照常采用。
5. 采用判定：`原估算 − 蒸馏估算 >= minSavedTokens` → 替换；否则记一条 `未采用`（开销照记）；调用失败/被中断/输出为空 → 记一条 `已放弃`（开销照记）。
6. 落盘：把该条目写进 sidecar（原子写：先写临时文件再 rename；目录 0700、文件 0600）。
7. **交接标记**：若总开关开且已选后端 → 记下"这条改写待交接"。

### D. 重放替换与记账（每次请求）
1. 宿主组装请求时会调用被包装的 `deriveMessages()`：
   - 逐条判定"改写是否**真的能应用**"：条目未被放弃/未采用、未被标记失效、目标 seq 仍在模型可见 surface 上、**当前消息 id 与记录一致**、该消息**仍有能替换的 reasoning 块**；全部满足才替换，并**记录本次请求实际应用了哪些条目**。
2. 回答落地时（`assistant/message`）用**那一次请求的记录**结算：命中的条目按 `savedTokensPerRequest × 单价` 计入；首次重放（或压缩改变前缀后的首次）按**未命中**价，其后按**命中**价。
3. 于是"生效"与"计费"永远同一判据：**没真正替换的绝不记账**。

### E. 请求前：卡住 → 交接 → 继续或终止（`agent/pre-step`）
1. `await ensureLoaded()`：确保记录可读（读不到则本步不压缩）。
2. `await settle()`：**等这次蒸馏彻底结束**（原分支在此期间卡住；活动指示器显示原因与已等待时间）。
3. **分支型后端**：若上一步压缩成功 → 宿主在**发出任何请求之前**调用后端建分支（时限 = `branchTimeoutMs`，0=永不超时）：
   - **成功** → 记录 `handoff: created`，返回 `{kind:'reject'}` **终止本回合**（原会话 0 次 API 调用），面板看到后**自动打开新分支**；
   - **失败/拒绝/超时** → 记录 `handoff: failed`（仅此痕迹），**当作无事发生**继续原会话。
4. **就地型后端**：宿主不调（这些端点需要浏览器凭据）→ 由面板在轮询中应用，随后调用 `handoff {cancel:false}` 清标记，**不打断你的回合**（它要发的那次请求已因重放替换而变短）。
5. 无待办 → `next()` 正常进入模型调用。

### F. 压缩（宿主 compaction）后的账务
- 目标被压掉的条目：live 金额结转到冻结、清零 live、标 `inactive`（**历史累计 token 与金额保留**）。
- 仍存活的条目：继续计费，并标记"下一次按未命中价"（前缀变了，那一区域要重发）。

### G. 持久化与接口
- 每会话一个 sidecar：`<DSH_HOME>/reasoning-distill/<会话 id 净化 + sha256 前 16 位>.json`；原子写、串行队列、单飞读；损坏/无权限 → **失败关闭**（不覆盖、不发起付费调用），文件可读后自动恢复；旧命名记录只有**自证归属**才采纳，损坏的旧文件按"不可读"处理。
- 路由：`POST /api/reasoning-distill/report`（报告）、`GET /api/reasoning-distill/catalog`（模型目录）、`POST /api/reasoning-distill/handoff`（清交接标记 + 按需停止回合）。
- 客户端轮询：会话页每 4 秒（并在窗口重新聚焦时）读一次报告；输入框指示器每 2 秒。响应按"已应用的最新序号"排序，慢响应不会丢、旧响应不会覆盖新状态。
