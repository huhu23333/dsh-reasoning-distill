# 验收说明：设置项 / 显示项 / 后台处理逻辑

> 对照版本：git `a0c60a9`（`npm run check` 全绿：宿主 smoke 165 项 + 客户端 render 99 项，`npm run typecheck` 宿主+客户端 0 错误）

---

**持久审计前置要求**：本插件要求宿主提供 `sessionPersistence` 服务（例如启用 JSONL 会话持久化后端）；否则拒绝加载，并明确报告缺少 `sessionPersistence`，不再悄悄创建重启后消失的内存审计会话。蒸馏调用有 provider `usage` 时输入/缓存命中/输出用真值；没有返回 usage 时才估算并标注。思考原文、改写文本的 token 为估算：按用户提供的官方换算口径，中文/CJK 每字符约 0.6 token、其他字符约 0.3 token，取整；宿主目前未暴露准确的文本 tokenizer。

## 一、设置项（设置 → 推理蒸馏）

设置页自上而下的区段：**总开关 → 助手消息改写后端（含分支超时）→ 默认规则 → 逐模型规则 → 价格 → 提示词**。

### 1. 总开关

| 设置项 | 默认 | 含义 | 影响 |
|---|---|---|---|
| 启用思考压缩（`enabled`） | 关（默认） | 插件总开关。关闭后不再有任何蒸馏调用 | **未选择改写后端时被强制关闭并置灰**（面板、引擎、报告三处一致）；选择后端后解锁，是否打开由你决定；**存的后端本版本不认识 / 是占位条目 / 其插件不在 profile 的已启用清单里 / 是宿主补丁型而宿主自检明确回答没有补丁时，宿主在启动后第一次 pre-step 会清空该选择并把它写成关**（见三、E.0） |

### 2. 助手消息改写后端

| 设置项 | 默认 | 含义 |
|---|---|---|
| 助手消息改写后端（`rewriteBackend`，单选） | **空（不选）** | 谁来把蒸馏结果**写回会话历史**。只列出**可用**的后端（探针规则见下），不可用的置灰；**宿主补丁型后端（`in-place`）还要通过宿主补丁自检（`patched` 且 `functional`）才可选**；点已选中的那行=取消选择 |
| 分支超时（毫秒）（`branchTimeoutMs`） | **0** | 宿主等待**分支型**后端建好分支的时限；**0 = 永不超时**。仅选中分支型后端时可编辑，否则置灰 |

两个后端条目及其契约：

| id | 前置插件 | 请求 | 语义 | 谁来调用 |
|---|---|---|---|---|
| `message-edit` | `dsh-message-edit`（或 `@yunyv/dsh-message-edit`） | `POST /message-edit {action:'splice', sessionId, eventSeq, blockIndex, text}`（`edit` 会丢工具调用与后续步骤，故不用） | **另开分支会话**（新版本，原会话不动） | **宿主**（`127.0.0.1:<webServer.port>`，无需浏览器凭据）→ 在 `agent/pre-step` 内提交；成功后当前回合被 reject、由新分支接管，失败则原回合正常答复 |
| `in-place` | —（无；**由本插件自己的宿主半边提供服务**，前置条件是宿主补丁） | `POST /api/reasoning-distill/rewrite {sessionId, eventSeq, blockIndex, text}`（**消息 id 由宿主从 sidecar 记录里取**，请求体不带） | **就地改写日志本身**：同一个 seq、同一条消息就地换掉 reasoning 块，日志长度与所有 seq 不变 | **面板/常驻芯片**（该路由在 `/api/*` 后面，需要浏览器凭据）→ 应用后调用 `handoff {cancel:false}` |

**安装探测**（界面挂载时对每个**有探针**的后端发一次探针）：**`404` 且响应不是 JSON** 才算"未安装"——已安装的后端连自己的错误（会话不存在、请求体不合法）也是用自己的 JSON 信封回答 404。**宿主补丁型后端多一道**：`in-place` 的探针打的是本插件自己的路由，能回答只证明插件加载了，所以还要看响应体里的 `{ patched, functional }` 自检，两个都为 `true` 才可选（纯函数 `backendSelectable` / `hostPatchReady`）。

> 此前这里列的后两个后端（`msg-edit` / `context-shaping`）都是未验证的 in-place 型，已连同它们的契约、安装条目、文案、打包脚本与 vendor 产物一起移除；in-place **机制**（前端写回驱动、认领标记、`handoff {cancel:false}`）保留在代码里，现在由本插件内置的 `in-place` 后端使用。
>
> **内置 `in-place` 的宿主补丁**：补丁给宿主 `Session` 加上 `rewriteReasoningBlock`，并在 `SessionHandle` 上加上可选的 `rewrite`（append-only 的事件流表达不了「原地替换」，jsonl 侧以「整份重新编码 + 原子替换」落地）。`--apply` / `--check` / `--revert` 由 `scripts/dsh-inplace-patch.mjs` 一条命令负责：逐条字面编辑、锚点对不上就整体拒绝、脏文件守卫只放过本补丁自己写脏的文件。**落盘实验**（`scripts/probe-inplace-durability.mjs`）证明改 → flush → 换新 Context 读回拿到的是改写后的文本（`none` / `zstd` 都跑过）。**语义变化**：原 reasoning **不再留在日志里**，审计只能依赖 sidecar 的 `distill.requestText` / `distill.responseText`。

### 3. 默认规则 / 逐模型规则（同一组字段）

| 字段 | 默认 | 含义 |
|---|---|---|
| `enabled` | 开 | 对**主对话**启用 |
| `continuableSubagents` | 开 | 对**可续接子代理**（队友等）启用 |
| `continuableMaxDepth` | 0 | 可续接子代理的**最大生效深度**（0=不限制） |
| `oneShotSubagents` | 关 | 对**一次性子代理**启用 |
| `oneShotMaxDepth` | 0 | 一次性子代理的**最大生效深度**（0=不限制） |
| （两条子代理开关被钉死） | — | 选中**分支型后端**（`message-edit`）时，两条子代理开关强制为关并置灰：分支接不住委派关系，在子代理里交接会打断该次委派。宿主在**首次 pre-step 自检**里写回设置（`subagentKindsOffPatch`），引擎的 `appliesTo` 也直接拒绝子代理会话（手改配置同样无效）。换非分支后端即可恢复 |
| `thresholdTokens` | 4000 | **触发门槛**：该步思考估算 token 超过它才尝试蒸馏 |
| `minSavedTokens` | 600 | **采用门槛**：蒸馏后若 `原估算 − 蒸馏估算 < 此值` 则**不替换**（记"未采用"条目，开销照记） |
| `includeToolResults` | 开 | 是否把该步工具**结果**作为背景交给蒸馏 |
| `includeFinalTurns` | 开 | 最终回答那一轮（无工具调用）是否也压缩 |
| `timeoutMs` | 0（不限） | **单次蒸馏**时限；0 = 不设时限。设了时限时，超时即放弃该次压缩、原文不动 |
| `distiller` | deepseek-official / deepseek-flash / off | 蒸馏用的 provider/模型/推理档 |
| `maxInputChars` | 0（不限） | **背景块**（每个工具结果各自一块）的长度上限；0 = 不截断。**它绝不截断被改写的思考本体**：设了上限时，思考超过该值会**跳过这次压缩**（不花钱、原文不动），而不是只把前半段送去蒸馏；0 时不做这个跳过判断，多长都整份交给蒸馏器 |
| `maxOutputChars` | 0 | **蒸馏结果**长度上限，0=不限 |

四种会话种类的开关各自独立；**每条规则三档全关**时其余字段置灰（不可能生效）。逐模型条目**稀疏存储**：只写被改过的字段，其余继续跟随默认规则。

## 二、显示项

### 会话页 → 推理蒸馏 标签

**四张金额/数量卡**（符号约定统一为"一本账"：**正数=多花，负数=省下**，红正绿负）：

| 卡片 | 主值 | 小字 | 含义 |
|---|---|---|---|
| 触发次数 | **成功 X** | 尝试 Y · 约 **−Z** tokens（历史减量） | 成功=真正采用了改写的条目；尝试=记过的条目总数（含蒸馏失败、节省不足未采用） |
| 蒸馏开销 | **+¥…** | 蒸馏 input+output token | 各次蒸馏**实际花掉**的钱（失败/超时/未采用也计） |
| 当前单次请求减量 | **−¥…** | 约 **−N** tokens · 口径说明 | **存量**：此刻仍生效的改写让**这一次请求**少带的估算 token，金钱按**命中价**估算；不随请求次数增长 |
| 历史累计节省 | **−¥…** | 约 **−N** tokens（历史累计） | **流量**：每次确实带着这些改写发出的请求，按**那一次实际适用价格**结算并累加，**永不重置**（条目失效后其历史贡献保留） |
| 净收益 | **−¥…**（省）/ **+¥…**（亏） | 同上累计 | 历史累计节省 − 蒸馏开销 |

**说明文案**：存量口径、符号约定、整段压缩后的归零规则。

**进行中区**：正在运行的压缩（轮次/步、蒸馏器、原 token→当前）、阻塞横幅（原因：工具调用中/等待用户/其它 + 已等待秒数）。

**触发记录（逐条，可展开）**：
- 折叠行右侧：**`+增加开销 − 已避免开销 = 实际开销变化量`**（右对齐、红正绿负）；
- 展开后：该步**原文思考**（可复制）、**蒸馏结果**（可复制）、每次蒸馏的模型/耗时/输入·缓存·输出 token/费用/时段，以及**当前单次请求减量**（token）与**已避免开销（负数）**、**一手历史累计 token**；
- **分支交接记录**：成功→「已创建分支 <id>」；失败→「分支创建失败：<原因> · 已按原会话继续」。

候选模型列表**只列尚未加入的模型**（已加入的不再出现在候选中）。

**压缩会话列表**（页面内的会话行）：每条压缩对应的会话 id；**仍在线的会话提供「打开」** ✓；来自上次运行的**死 id** 只标注「会话已随上次运行结束」而**不提供打开**（死 id 打不开，给按钮只会误导 ✗）；完整提示词/结果**始终**在该条明细里 ✓（审计的正本在这里）。**会话标题栏的那份重复列表已移除**（这里已经能开，头部不再重复）。

### 输入框活动指示器（composer）

压缩进行中/等待压缩完成时显示状态与原因，并**向宿主申请展开空间**（宿主据此隐藏模型/右侧控件）；压缩结束或读取失败即回到静默。

### 设置页自身的状态显示

保存状态（未保存/保存中/已保存/冲突/失败），目录加载失败提示与重试按钮，模型候选列表（可搜索、已加入项标 ●）。

## 三、后台处理逻辑（逐步）

### A. 会话接入（`session/created`）
1. 记录会话归属（自身创建的审计会话不参与）。
2. `Object.defineProperty` 包装该会话的 `deriveMessages()` **与 `deriveEventMessage()`**（后者是宿主 compaction 逐节点重建输入的那条缝）；同时保存**原始**派生函数（存量计算、以及本插件自己的判据都读它，避免读到自己的改写）。
3. 预读该会话的 sidecar（fire-and-forget，单飞）。

### B. 逐步观察（`session/event`）
- `assistant/message`：
  1. 忽略中断（`interrupted`）的步骤；忽略非助手消息。
  2. 取该模型规则；判定**会话种类**（主对话/可续接/一次性）与**深度上限**，三档开关逐一放行。
  3. 估算该步 reasoning 的 token：低于 `thresholdTokens` → 不处理。
  4. 记住该步的载体信息（turn/step、消息 id、**reasoning 块下标**、可见 text 块与工具调用块）。
  5. **记账**：以"事件发生时刻的 surface 快照"判定该请求实际带上了哪些改写，按命中/未命中价累加（详见 D）。
- `step/end`：
  1. **先读记录**（`ensureLoaded`）：读不到（损坏/无权限）→ 标记该会话存储不可用，**跳过本步**，不花一分钱。
  2. 读得到 → `launch` 启动蒸馏（后台异步），并把这一整套登记为 in-flight。
- `compaction/end`：逐条判定改写是否仍会被应用，失效者结转 `frozenSaved`、标记 `inactive`；仍存活者保留并标记"下一次按未命中价结算"。

### C. 一次蒸馏（`compress()`）
1. 组装输入：`## Original reasoning`（要改写的部分）+ `## Assistant text from this step`（该步可见 text，**背景**）+ `## Tool calls from this step`（**背景**）+ `## Tool results`（按 `includeToolResults`，**背景**）；三段背景都标注 `(context only, never copy)`。
2. 用该规则的 `distiller` 发一次独立调用（超时按 `timeoutMs`，0=不限）；输出长度按 `maxOutputChars` 裁剪。
3. 用量与费用：优先用返回的 usage，缺失则按字符估算并标记"估算"；费用按当时时段/命中·未命中价折算。
4. 创建**审计会话**（把完整提示词与结果写进它的持久化日志）；创建失败记 `sessionMissing`，但压缩照常采用。
5. 采用判定：`原估算 − 蒸馏估算 >= minSavedTokens` → 替换；否则记一条 `未采用`（开销照记）；调用失败/被中断/输出为空 → 记一条 `已放弃`（开销照记）。
6. 落盘：先写私有临时文件（目录 0700、文件 0600），再检查截止时间与会话世代；若等待已放行原文，另备一份 `failed` 记录。只发布最终选中的文件：同步 rename 后立即更新缓存，中间不让出事件循环；回退写入失败也不会把未获批准的改写留在磁盘上。
7. **交接标记**：只有截止前提交的已采用条目才公开并可记为待交接；若临时文件写入期间已放行原文，最终只提交失败记录、节省为零，不再替换该条思考；若提交后、发起分支交接前才过截止，保留已采用条目并持久记录 `handoff: skipped`，绝不迟到创建截断分支。

### D. 重放替换与记账（每次请求）
1. 宿主组装请求时会调用被包装的 `deriveMessages()`；宿主的 compaction 逐节点重建输入时调用被包装的 **`deriveEventMessage()`**。两者由**同一套判据**回答（`rewriteKind`），所以「请求带什么」与「压缩读什么」逐字节相同：
   - **替换并计费**：条目未被放弃/未采用、未被标记失效、目标 seq 仍在模型可见 surface 上、**当前消息 id 与记录一致**、该消息**仍有能替换的 reasoning 块**；满足才替换，并**记录本次请求实际应用了哪些条目**。
   - **只洗 replay 载荷、不计费**：日志里已经是这条蒸馏文本（更早的分支 splice 进来的）——文本已经对，只有 replay 载荷还描述着被替换掉的原文（含签名），洗掉它；这份节省属于接管的那个分支，此处不记账。
   - **把日志自己的消息放回那一格**：既不在本会话生效、日志也不是蒸馏文本时（失败条目、已交接给分支、用户改过原文）——防止"交接之前某次派生缓存下来的替换"活过交接。判据一律读**日志自己的**消息（`rawMessageOf`），不读已被本插件改写过的那份。
2. 回答落地时（`assistant/message`）用**那一次请求的记录**结算：命中的条目按 `savedTokensPerRequest × 单价` 计入；首次重放（或压缩改变前缀后的首次）按**未命中**价，其后按**命中**价。
3. 于是"生效"与"计费"永远同一判据：**没真正替换的绝不记账**（洗 replay 载荷那条不产生记账）。

### D-1. 结算判据（第 1 轮评审后的收紧）

1. **只认请求边界的一次派生**：宿主每次请求先经过 `agent/request` waterfall，再由 `buildRequest()` 派生并冻结消息；插件在 waterfall 完成后布防，只消费其后第一次派生，之后的查看器/旁路派生不覆盖已冻结归属。残余限制：若另一个插件在该 waterfall 结束后、宿主 `buildRequest()` 前抢先派生，宿主未提供更细的冻结回调，本插件可能把那次派生错认作请求；宁可限制归属窗口，不延长到整个 step。未经过 `agent/request` 的内部请求没有归属记录，仅按既有 surface 兜底。
2. **记录带 surface 指纹**，比对时**先裁掉本次响应自己刚追加的节点**（响应事件落地时它已经在 surface 上）✓；
3. **归属由记录本身决定**：结算取"**该响应之前、最近一次在请求边界窗口内产生的记录**"（`afterSeq <= 响应 seq` ✓）。**不再**把整段 surface 的节点集当判据 ✓ —— 那种比对会把"**已经真正发出去**的节省"追溯抹掉 ✗。
4. 只有会话**完全没有**请求记录时（恢复的事件、夹具、未走 pre-step 的路径）才回退用"目标仍在 surface 上"判断 ✓。
4. **精确口径**：一次性节省**跟随那次冻结请求实际携带的字节** ✓ —— 请求组装**之后**才发生的投影（就地改写等）**不追溯撤销**已发生的节省 ✓（它只影响**下一次**请求的判定与**存量/显示** ✓）。这样规范与"请求即事实"的计费一致 ✓，也避免把真实发生过的节省误判为 0 ✗。
5. **内容指纹**：条目另记**蒸馏来源思考的指纹**（`originalHash` ✓）；同 id、同 seq 下思考被**编辑**后 ✓，该条目**不再替换** ✓（不改写用户的编辑 ✓），下一次请求的判定直接反映出来 ✓。

### E. 请求前等待与空闲时分支交接（`agent/pre-step`）
0. **每个进程一次的启动自检**（在任何规则判定之前，与本次是否触发压缩无关）：按 `<profile>/package.json` 的 `dsh.profile.bundles`（经 `profileContext.dir` 定位）判断存的那个后端还能不能用——只读 `bundles` 不读 `dependencies`，因为后者里的包可能只是装了但没启用、不提供路由；宿主够不到后端路由（`/api/*` 要浏览器凭据，宿主自己问只有 401），所以宿主侧只能看这份清单加上自己的注册表。**用不了**有四种（纯函数 `backendUnusable`）：① 该 id **本版本不认识**（被删掉的后端、别的版本写的值）；② 该 id 是**占位条目**（没有实现，且它那行是禁用的，面板自己清不掉，只有宿主能清）；③ 它登记了插件名而清单里没有；④ 它是**宿主补丁型**后端而宿主自检**明确回答没有补丁**（`hostPatch === false`）——还没问过时（`undefined`）什么都不动，否则第一次 pre-step 就会把可用配置清掉。宿主补丁型的判定不看清单：它的路由是本插件自己的。此时：打一条 warn，并**写一次**设置（`settings.update('reasoning-distill', …)`，与面板保存同一条路径、同样落盘）——**清空选定后端 `rewriteBackend: ''`**，总开关仍为开则**同时**写 `enabled: false`，已关则只清空选择（`missingBackendFixup` 纯函数决定这组字段；选中的名字比它依赖的东西活得久）。**读不到清单 → 一律不改配置**（对这个宿主没有任何证据）。「装着但已停用」等同于用不了。自检由 `backendChecked` 保证进程内只跑一次；它排在同步序言（单飞登记与等待上限的计算）之后、本次请求任何规则判定之前。
1. `await ensureLoaded()`：确保记录可读（读不到则本步不压缩）；有限规则的等待也以该规则自己的 `timeoutMs` 为截止（**不加任何宽限**；`ruleBackstopMs()` 取各规则上限的最大值，任一条为 0 即视为不限），重入不重新计时，过期后放行原请求并禁止同一挂起门闩迟到启动。
2. `await settle()`：**等这次蒸馏彻底结束**（原回合在此期间等待；活动指示器显示原因与已等待时间）。
3. **分支型后端**：压缩成功后，在**当前 `agent/pre-step` 内**直接向后端提交一次非幂等 POST（`action:'splice'`，等待上限 = `branchTimeoutMs`，0=永不超时）；下一次请求的 `deriveMessages` 替换与建分支成功与否无关：
   - **成功** → 记录 `handoff: created` + `branchId`，面板轮询后**自动打开新分支**；当前回合当场 `return {kind:'reject'}`，后续步骤在新分支里带着压缩后的上下文继续（原回合不重排输入、也不追加合成消息）。
   - **失败/拒绝/超时** → 如实记录 `handoff: failed`（或尚未 POST 前等待耗尽时 `skipped`）；不唤醒、不重发用户输入，**原回合照常继续**；历史重放替换仍生效。另有空闲兜底（`scheduleBranchAtIdle`：宿主暴露 `agent.whenIdle` 时，`whenIdle()` 之后再试一次 POST）——这条路径**是可达的**：`handOffToBranch` 的失败出口只在 generation 未变时才清掉待交接条目，而会话销毁/替换会递增 generation（`forgetSession`），所以交接途中会话被销毁/替换时条目会留下，下一次 `agent/pre-step` 就会触发这个兜底。宿主不暴露 `whenIdle` 时**不在 pre-step 之外补记失败原因**——曾有一个只负责这件事的 `failMissingIdleAgent`，它没有任何调用者，且它要记的原因会与 `handOffToBranch` 已经写下的重复，已作为死代码删除（见审查台账 B14；不是行为差异）。
   - **宿主边界，非插件缺陷**：分支后端在 `agent/pre-step` 阶段读源会话日志，不需要宿主的 maintenance 阶段，所以分支能在当前回合内就建好——这正是「在 pre-step 内 POST、成功即 reject」这一设计的原因（旧设计「先停回合再建分支」不可达：`runMaintenance` 在源 Agent 非 `idle` 时会直接抛错，DSH checkout 的 `packages/core/agent-loop/src/agent.ts:183-185`）。idle 到领取 maintenance 之间的 Stop 在宿主层是 no-op（`packages/core/agent/src/runtime-types.ts:176-179`），属于已知宿主边界，非本插件能修复。
4. **就地型后端（内置 `in-place`）**：宿主不调（这条路由需要浏览器凭据）→ 由面板/常驻芯片在轮询中应用，随后调用 `handoff {cancel:false}` 清标记，**不打断你的回合**（它要发的那次请求已因重放替换而变短）。应用路径 `engine.applyInPlace` 会**再次确认补丁存在**，并**从 sidecar 记录里取目标消息 id**（调用方只能给 seq 与块下标）；补丁不在了就拒绝，并走与启动自检同一条「清选择 + 关总开关」的写入路径。
5. 无待办 → `next()` 正常进入模型调用。

### F. 压缩（宿主 compaction）后的账务
- 目标被压掉的条目：live 金额结转到冻结、清零 live、标 `inactive`（**历史累计 token 与金额保留**）。
- 仍存活的条目：继续计费，并标记"下一次按未命中价"（前缀变了，那一区域要重发）。

### G. 持久化与接口
- 每会话一个 sidecar：`<DSH_HOME>/reasoning-distill/<会话 id 净化 + sha256 前 16 位>.json`；原子写、进程内串行队列、单飞读；损坏/无权限 → **暂停付费压缩且不覆盖记录**，但请求派生仍回退到日志原文以保持会话可用，恢复可读后前缀可能再次改变；旧命名记录只有**自证归属**才采纳，损坏的旧文件按"不可读"处理。同一 `$DSH_HOME` 需要单宿主写入：多进程的队列互不协调，后写者可能覆盖先写者的条目。
- `skipWhileBusy` 只覆盖宿主 job 注册表。`dsh-ops` 的 FastCtx 私有后台作业不在其中，自动分支交接可能让新会话失去这些作业的 output/kill 权限；在这类作业结束前应避免自动分支交接。
- 路由：`POST /api/reasoning-distill/report`（报告）、`GET /api/reasoning-distill/catalog`（模型目录）、`POST /api/reasoning-distill/handoff`（清交接标记 + 按需停止回合）、`GET|POST /api/reasoning-distill/install`（后端安装：`GET` 读当前作业 / 可安装后端 / 步骤 / 插件目录，`POST` 传 `action:'start'|'cancel'`；安装跑在宿主进程里，关掉页面不中断）、`GET|POST /api/reasoning-distill/rewrite`（内置 `in-place` 后端：`GET` 报宿主补丁自检结论，`POST {probe:true}` 用同一结论回答面板探针，`POST {sessionId,eventSeq,blockIndex,text}` 执行一次改写，未打补丁时 503）。
- 客户端轮询：会话页每 4 秒（并在窗口重新聚焦时）读一次报告；输入框指示器每 2 秒。响应按"已应用的最新序号"排序，慢响应不会丢、旧响应不会覆盖新状态。

## 四、对 `dsh-whale-widget` 的依赖

**没有强制依赖，缺失时自动落回内置**：

- 插件**从不 import** 该 widget；`peakSource: 'whale'` 只是可选项（默认是 `builtin`）。
- 选择 `whale` 时，`peak.ts` **只读**它的 bundle 文件（`<profiles>/<profile>/node_modules/dsh-whale-widget/lib/index.js`）解析峰谷时段与节假日常量，属 best-effort；读不到即返回 null。
- 读不到时的行为：`resolvePeakSource()` 直接返回**内置固定时窗**（北京时间 9–12、14–18 为峰；周末与内置节假日全天谷价），并在设置页说明「未找到 dsh-whale-widget 的峰谷常量，已回退到内置固定时窗。」；`whaleStatus()` 报「未检测到」，设置页的"按 widget 重置节假日"按钮相应禁用。
- 因此在**未安装** `dsh-whale-widget` 的机器上，本插件所有功能（含峰谷计价）都正常工作。

## 五、第 2 轮评审后的补充契约

**取消优先于请求前等待**：`agent/pre-step` 里的读记录 `ensureLoaded`、等蒸馏 `settle` 都并入宿主中止信号；分支 POST 就在同一个 `agent/pre-step` 内进行，成功即 `{kind:'reject'}` 结束当前回合、由新分支接管，不把待答用户输入丢在 blocked turn。宿主的信号只在 `agent/pre-step` 返回后才检查，所以插件必须自己把信号并进等待，否则"停止"会排在压缩后面 ✗（第 2 轮评审 high 级发现，已修）。

**"卡住"的上限从哪来**：由**该次压缩自己的规则**决定——`timeoutMs > 0` 时蒸馏调用本身在该值处中止，等待也以**同一 `timeoutMs`** 为上限（`ruleBackstopMs()` 取各规则上限的最大值，**不额外加宽限**，作为"适配器不理会 abort"的兜底）；`timeoutMs = 0`（文档语义为"不限"）时**没有自动上限**，但**停止依然随时有效** ✓。

**会话世代**：会话对象只 attach 一次，但**同一个会话 id 可能再次出现**（清空/重建/重载）。每次 attach 会递增该 id 的**世代号**并清空它的全部状态：按 id 直接记账的 `pendingBranch`/`pendingArchive`/`deferredBranch`/`expectRequest`/`loadStarted`/`blocked`/`applied`/`rawDerive`/`storageBroken`，按 `${sessionId}:` 前缀记账的 `pending`/`inFlight`/`running`/`waitBound`/`owedHandoffNotes`/`handoffOrder`/`committedHandoffOrder`/`missCharged`/`abandoned`/`abandonTimers`/`auditBroken`，以及 sidecar 存储里该会话记录的内存副本（含原始推理原文，见审查台账 B27）；上一世代仍在跑的压缩在**每次落盘或标记交接前**校验世代号，不符即**放弃写入** ✓。否则旧世代的压缩会让新会话的请求平白等待（`settle` 按 id 前缀匹配 ✗）并把陈旧改写写进新会话记录 ✗。

**世代检查必须在写队列内部**：`store.update()` 是**按会话串行排队**的 ✓，所以"写之前检查一次"并不够 ✗——排队期间世代就可能已经改变 ✓。因此所有落盘都在 `mutate` **内部**判定世代，不符即放弃写入 ✓。

**门闩与迟到事件也要守世代**：`step/end` 的门闩在异步读完记录后会**再次校验世代**（不符则不 launch、不登记）✓；`launch` 只接受仍属于当前会话对象的候选目标 ✓；已销毁会话对象排队的迟到事件**一律忽略**（按会话对象身份判定）✓。

**无候选步骤不登记门闩**：`step/end` 时若该步没有候选目标（无思考、低于门槛、规则关闭、未选后端），**不创建也不登记** in-flight 门闩；否则每步都会留下一个已完成的 promise，长期累积并拖慢后续 `settle` 的扫描 ✗（第 2 轮评审 medium 级发现，已修）。

**不可确认的分支创建**：分支型后端的请求**没有幂等键** ✓，因此"请求已发出但未收到响应"（超时、连接中断 ✓）属于**结果不可知** ✓ —— 此时插件按"失败"记录 ✓，但错误文本会**明确写出**"可能已创建了本插件无法命名的分支" ✓。**我们不会自动去认领**那个可能存在的分支 ✓（无法可靠匹配 ✓，且认错分支比留一个孤立会话更糟 ✗）：如确需清理，请在后端自身的会话列表里按时间判断 ✓。

**多 reasoning 块消息不压缩（已知限制）**：重放会把一条消息里的**所有** reasoning 块合并成一条 ✓，而分支型后端一次只替换**一个**块 ✓ → 若压缩多块消息 ✓，分支里会留下**其余原文** ✓（泄漏未压缩内容 ✓，且与报告的节省不符 ✗）。因此本插件**只压缩恰好一条 reasoning 块**的消息 ✓（0 条或 2 条以上都跳过并记日志 ✓）：宁可少压，也绝不制造"重放与分支不一致" ✗。

**后端响应的判定**：后端响应体形状不统一，因此**缺 `ok` 字段视为成功**、**显式 `ok: false` 视为拒绝**、**非 2xx 一律失败** ✓；失败会记录在条目上并显示，绝不会静默算作完成 ✓。（内置 `in-place` 返回 `{ok:true,eventSeq}` 或 `{ok:false,error}`，走同一条判定；`rewriteApplyOutcome` 的纯函数测试仍在。）

**就地交接的重载限制**：面板在后端请求结束后、向宿主发送 settle 前，把该次结果按 `${sessionId}:${entryId}` 记入当前标签页的 `sessionStorage`；同标签页重载或视图重新挂载只重试 settle，不重复发送非幂等的后端 POST。此记录不跨独立标签页共享；当 `sessionStorage` 不可用（包括读取属性本身抛错）或被清空时，跳过当前标签页的防重复保护，面板仍继续调用后端并 settle，不会因存储不可用而崩溃；若请求已在后端生效但页面在收到响应并记入存储前中断，结果也仍不可确认。这些情形可能重复发送，后端本身没有幂等键可供消除该风险。
